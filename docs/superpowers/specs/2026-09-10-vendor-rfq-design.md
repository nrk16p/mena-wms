# ฟอร์มขอราคาอู่ผ่านลิงก์ (Vendor RFQ) — Design

วันที่: 2026-09-10 · สถานะ: อนุมัติแล้ว (review 2026-09-10: ผู้ใช้ให้รวมอะไหล่ในรอบแรก แยกเป็นคนละหน้ากับค่าแรง ที่เหลือตามสมมติฐาน)

## 1. ปัญหาและเป้าหมาย

ฝ่ายจัดซื้อมี **แคตตาล็อกงานช่างมาตรฐาน 99 งาน** (13 ระบบ × Mixer L/S) อยู่ในไฟล์
`~/Documents/project/ฟอร์มขอราคา_งานช่างมาตรฐาน_MixerL-S.xlsx` และต้องการให้อู่ในทะเบียน AVL
(`/vendors`) เสนอราคาค่าแรงตามแคตตาล็อกนี้ เพื่อนำมาเทียบกันและตั้งเป็นราคากลาง

วิธีเดิม = ส่งไฟล์ Excel ให้อู่ทาง LINE แล้วรอไฟล์กลับ ปัญหาคือ
- อู่ส่วนใหญ่เปิด LINE บนมือถือ กรอก Excel 19 คอลัมน์ไม่ไหว ตอบช้าหรือไม่ตอบ
- ไฟล์ที่กลับมาสะกดชื่ออู่ไม่ตรง ใส่ราคาผิดช่อง ต้องคีย์ซ้ำเข้าระบบเอง
- ไม่รู้ว่าใครเปิดดูแล้ว ใครกรอกค้าง ใครส่งแล้ว ตามงานไม่ได้
- ราคาที่ได้ไม่มีวันหมดอายุ ไม่รู้ว่ายังใช้ได้ไหม

**Flow ที่ตกลง (ผู้ใช้กำหนด 2026-09-10):**
1. จัดซื้อเลือกอู่ที่ต้องการให้เสนอราคา + เลือกประเภทการซ่อม แล้วกด **สร้างลิงก์**
2. นำลิงก์ไปส่งอู่ (LINE) — อู่เปิดได้เลย **ไม่ต้อง login** กรอกแค่ ชื่อผู้ติดต่อ + เบอร์โทรหรืออีเมล + ยืนยันชื่ออู่
3. อู่กรอกราคา แล้วกด **ส่งใบเสนอราคา** เมื่อข้อมูลครบ
4. จัดซื้อ **ตรวจสอบ** แล้ว **ยืนยันการเสนอราคา** พร้อม **กำหนดวันที่ราคามีผล** (เริ่ม–สิ้นสุด)
5. อนาคต: สร้าง PDF ให้อู่เซ็นยืนยัน / ขอหลักฐานแนบ

**สิ่งที่มีอยู่แล้วและใช้ต่อ:**

| ของเดิม | ที่อยู่ | ใช้ยังไง |
|---|---|---|
| ตารางความสามารถอู่ (codes S30–S101 ที่ติ๊ก) | `/vendors`, `vendor_approval` | ค่าตั้งต้นว่าอู่รายนี้ควรได้ระบบไหนบ้าง |
| ทะเบียนประเภทการซ่อม | `lib/repair-type-master.ts` | ชื่อชีตในฟอร์มคือรหัส S เดียวกัน (S45 ระบบโม่ ฯลฯ) |
| ฟอร์ม Excel 13 ระบบ | ไฟล์ xlsx ข้างบน | นำเข้าเป็นแคตตาล็อกใน DB ครั้งเดียว (ข้ามชีต ปะหน้า/แคตตาล็อก/รหัสเดิม) |
| PDF stack (pdfmake + Sarabun) | `lib/pdfmake-printer.ts` (จาก price-compare) | เฟส 2 ออก PDF ให้เซ็น |
| ราคากลาง price-benchmark | mena-intelligence | เฟส 2 เทียบราคาที่อู่เสนอกับราคากลาง |
| ยกเว้น middleware สำหรับ route public | `middleware.ts` (แพตเทิร์น `/api/cron/*`) | เปิด `/q/*` + `/api/q/*` |

**เป้าหมายรอบนี้ (เฟส 1):**
1. สร้างลิงก์รายอู่จากหน้า AVL เลือกระบบได้ (ค่าตั้งต้นจากช่องที่ติ๊ก) + ตั้งวันปิดรับ
2. ฟอร์มสาธารณะบนมือถือ แยก **2 หน้า**: **ค่าแรง** ตามแคตตาล็อก (รายชั่วโมง หรือ เหมา เบา/กลาง/หนัก × Mixer L/S) และ **อะไหล่** (฿/หน่วย L/S, ยี่ห้อ, รับประกัน, ส่งมอบ) บันทึกร่างอัตโนมัติ ส่งเมื่อครบจากหน้าหลัก
3. หน้าจัดซื้อ: รายการลิงก์ทั้งหมด + สถานะ (ยังไม่เปิด/กำลังกรอก/ส่งแล้ว/ยืนยันแล้ว/หมดอายุ), หน้าตรวจรายใบ, ปุ่มยืนยัน + วันที่ราคามีผล, ส่งกลับให้แก้, ยกเลิก
4. Export Excel ใบที่ยืนยันแล้วในเลย์เอาต์เดิมของฟอร์ม (จัดซื้อยังใช้ไฟล์ต่อได้)
5. ประวัติทุกการเปลี่ยนสถานะ (ใคร/เมื่อไหร่/จากอะไรเป็นอะไร)

**ไม่ทำในรอบนี้ (YAGNI):**
PDF ให้เซ็น, แนบหลักฐาน, เทียบราคาข้ามอู่/ราคากลางในหน้าเดียว,
OTP ยืนยันเบอร์โทร, แจ้งเตือน LINE/อีเมลอัตโนมัติ, rate-limit ตาม IP (Hobby ไม่มี KV — ใช้ token + วันหมดอายุแทน),
แก้แคตตาล็อกงานช่างในเว็บ (แก้ที่ xlsx แล้วนำเข้าซ้ำ)

## 2. Data model (db `master_data`)

### 2.1 `rfq_job_catalog` — แคตตาล็อกงานช่าง นำเข้าจาก xlsx

```ts
type RfqJob = {
  sheet: string          // "S45" | "S37" | … | "SVC"  (รหัสชีต = รหัส S ของ repair-type-master; SVC = งานพื้นฐานทุกระบบ)
  sheetTitle: string     // "ระบบโม่ผสม (Mixer)"
  seq: number            // ลำดับในชีต
  jobCode: string        // "MXS-RLR-INS" — unique
  name: string           // ชื่องาน
  scope: string          // ขอบเขตงานที่รวมในราคา
  tierCriteria: string   // เกณฑ์แบ่ง เบา/กลาง/หนัก (ข้อความหลายบรรทัด)
  refHoursL: number | null
  refHoursS: number | null
  version: number        // เลขรุ่นแคตตาล็อก (+1 ทุกครั้งที่นำเข้า) — ใบเชิญจับรุ่นตอนสร้าง
  active: boolean        // false = ถูกถอดในการนำเข้ารุ่นใหม่ (ใบเชิญเก่ายังอ่านได้)
}
```
- นำเข้าด้วย `scripts/import-rfq-catalog.ts <xlsx> [--apply]` อ่านชีตที่ชื่อขึ้นต้นด้วยรหัส S หรือ SVC เท่านั้น
  ส่วนที่ 1 (แถวหลังหัวตาราง "ลำดับ | รหัสงาน | …" จนถึงแถว "ส่วนที่ 2") และส่วนที่ 2 อะไหล่ · idempotent ด้วย jobCode / sheet+sku
- index `{ jobCode: 1 }` unique, `{ sheet: 1, seq: 1 }`

### 2.1b `rfq_part_catalog` — อะไหล่ ส่วนที่ 2 ของแต่ละชีต (843 รายการ)

```ts
type RfqPart = {
  sheet: string; sheetTitle: string; seq: number
  sku: string            // "LB06MX00229" — unique ต่อชีต (SKU เดียวโผล่หลายชีตได้ → key = `${sheet}|${sku}`)
  name: string; useWith: "L+S" | "L" | "S" | string; unit: string
  version: number; active: boolean
}
```
- นำเข้าจากสคริปต์เดียวกับงานช่าง (แถวหลังหัวตาราง "ลำดับ | รหัสอะไหล่ | …" จนจบชีต) · index `{ sheet:1, sku:1 }` unique

### 2.2 `rfq_invites` — 1 เอกสาร = 1 ลิงก์ = 1 อู่ (คำตอบฝังในเอกสารเดียว)

```ts
type RfqInvite = {
  _id: ObjectId
  token: string                     // 24 ตัว base64url จาก crypto.randomBytes(18) — unique index
  vendor: string                    // ชื่ออู่ตาม vendor_approval.vendor (ล็อก อู่แก้ไม่ได้)
  sheets: string[]                  // ระบบที่ให้เสนอ เช่น ["S45","S37","SVC"] — SVC ใส่ให้เสมอ
  catalogVersion: number            // รุ่นแคตตาล็อกตอนสร้าง — ฟอร์มแสดงงานของรุ่นนี้เท่านั้น
  title: string                     // ชื่อรอบ เช่น "ขอราคางานช่าง Mixer ก.ย. 69" (ใช้จัดกลุ่มในหน้า list)
  deadline: string                  // "YYYY-MM-DD" วันปิดรับ (อู่กรอก/ส่งได้ถึงสิ้นวันนี้ เวลาไทย)
  status: "สร้างแล้ว" | "กำลังกรอก" | "ส่งแล้ว" | "ยืนยันแล้ว" | "ส่งกลับแก้" | "ยกเลิก"
  // "หมดอายุ" ไม่ใช่สถานะที่เก็บ — คำนวณจาก deadline < วันนี้ && status ∈ {สร้างแล้ว, กำลังกรอก, ส่งกลับแก้}

  contact: { name: string; phone: string; email: string; confirmedVendor: boolean; at: string } | null
  openedAt: string | null           // ครั้งแรกที่มีคนเปิดลิงก์ (GET public)
  sections: ("labour" | "parts")[]  // ส่วนที่ให้เสนอ ค่าตั้งต้นทั้งสอง
  items: Record<string, RfqAnswer>  // key = jobCode — เฉพาะที่อู่กรอก (ค่าแรง)
  parts: Record<string, RfqPartAnswer> // key = `${sheet}|${sku}` — เฉพาะที่อู่กรอก (อะไหล่)
  submittedAt: string | null
  submitNote: string                // หมายเหตุท้ายใบจากอู่

  confirm: {                        // ตอนจัดซื้อกดยืนยัน
    by: string; email: string; at: string
    validFrom: string; validTo: string   // "YYYY-MM-DD" ช่วงที่ราคามีผล
    note: string
  } | null
  returnNote: string                // เหตุผลที่ส่งกลับให้แก้ (แสดงให้อู่เห็นบนฟอร์ม)

  createdBy: { name: string; email: string }
  createdAt: string; updatedAt: string     // ISO +07:00 (toBkkIso)
}

type RfqAnswer = {
  mode: "hourly" | "lump" | "skip"  // skip = อู่ไม่รับงานนี้
  L: { rate?: number; hours?: number; light?: number; mid?: number; heavy?: number }
  S: { rate?: number; hours?: number; light?: number; mid?: number; heavy?: number }
  sameAsL: boolean                  // ติ๊ก "S เหมือน L" → ฟอร์มคัดลอกค่า L ลง S ตอนบันทึก (เก็บค่าจริงทั้งคู่)
  warrantyMonths?: number
  note: string
  at: string                        // เวลาที่แก้ล่าสุด
}

type RfqPartAnswer = {
  skip: boolean                     // ไม่มีจำหน่าย
  priceL?: number; priceS?: number; sameAsL: boolean
  brand: string; warrantyMonths?: number; leadDays?: number; note: string
  at: string
}
```
- index `{ token: 1 }` unique · `{ vendor: 1, createdAt: -1 }` · `{ status: 1, deadline: 1 }`
- ทำไมฝัง items ในใบ: 1 ใบมีอย่างมาก 99 งาน (ขนาดไม่ถึง 100 KB) อ่านทีเดียวได้ทั้งใบ
  บันทึกร่างใช้ `$set: { "items.<jobCode>": … }` ทีละงาน ไม่ชนกันเอง

### 2.3 `rfq_log` — append อย่างเดียว (แพตเทิร์น `vendor_capability_log`)

```ts
type RfqLogEntry = {
  inviteId: string                  // ObjectId string
  action: "create" | "open" | "contact" | "submit" | "confirm" | "return" | "cancel" | "reopen" | "resend"
  from?: string; to?: string        // สถานะก่อน/หลัง
  by: string; byEmail: string       // อู่ = contact.name / "" · ระบบ = "อู่ (ลิงก์)"
  note?: string
  at: Date
}
```

## 3. หน้าจอและ API

### 3.1 ฝั่งจัดซื้อ (ต้อง login · nav กลุ่ม "อู่และคู่ค้า" เดียวกับ /vendors)

| หน้า | ทำอะไร |
|---|---|
| `/vendors` (เดิม) | เพิ่มปุ่ม "ขอราคา" ในแถบเครื่องมือ: ติ๊กเลือกอู่หลายรายจากตาราง (checkbox คอลัมน์แรก) → เปิด modal สร้างลิงก์ |
| modal สร้างลิงก์ | ชื่อรอบ, วันปิดรับ (ค่าตั้งต้น +14 วัน), ตารางอู่ที่เลือก × ชีต (ค่าตั้งต้นจาก SHEET_OF_CODE, ติ๊กเพิ่ม/ลดรายอู่ได้), ปุ่มสร้าง → แสดงลิงก์รายอู่พร้อมปุ่มคัดลอกทีละอู่ และ "คัดลอกทั้งหมด" เป็นข้อความ LINE (ชื่ออู่ + ลิงก์ + วันปิดรับ) |
| `/rfq` | รายการลิงก์ทั้งหมด กรอง ชื่อรอบ/สถานะ/อู่ · คอลัมน์: อู่, รอบ, ชีต, สถานะ (+หมดอายุ), ความคืบหน้า "กรอกแล้ว n/N งาน", เปิดล่าสุด, ส่งเมื่อ, ราคามีผลถึง · ปุ่มคัดลอกลิงก์, ต่ออายุ (แก้ deadline), ยกเลิก · แถบสรุปนับตามสถานะ |
| `/rfq/[id]` | ตรวจใบ: หัวใบ (อู่, ผู้ติดต่อ, ส่งเมื่อ) + แท็บ **ค่าแรง** / **อะไหล่** ตารางตามชีต อ่านอย่างเดียว (แสดง ชม.อ้างอิง ข้าง ชม.ที่อู่เสนอ, ช่องว่าง = อู่ไม่กรอก, "ไม่รับงาน" = skip) · ปุ่ม **ยืนยันการเสนอราคา** (modal: validFrom ค่าตั้งต้นวันนี้, validTo ค่าตั้งต้น +12 เดือน, หมายเหตุ) · **ส่งกลับแก้** (ต้องใส่เหตุผล → สถานะ ส่งกลับแก้ อู่แก้ต่อจากลิงก์เดิม) · **Export Excel** · ประวัติ (จาก rfq_log) |

API (getServerSession ทุกตัว · เขียน = ทุกคนที่ login เหมือน repair-external; ยืนยัน/ยกเลิก = isAdmin):

| Method · path | ทำอะไร |
|---|---|
| `POST /api/rfq` | body `{ title, deadline, invites: [{ vendor, sheets[] }] }` → สร้างหลายใบในครั้งเดียว คืน `[{ id, vendor, url }]` · ตรวจว่า vendor มีใน vendor_approval, sheets ⊆ ชีตที่มีในแคตตาล็อก, SVC ถูกเติมให้เสมอ |
| `GET /api/rfq?status=&title=&q=` | รายการ (ไม่ส่ง items กลับ ส่งแค่ `answered` = จำนวนงานที่กรอก และ `total` = จำนวนงานในชีตที่ให้) |
| `GET /api/rfq/[id]` | ใบเต็ม + งานในแคตตาล็อกรุ่นนั้นของชีตที่ให้ (join ฝั่ง server) |
| `PATCH /api/rfq/[id]` | `{ action: "confirm", validFrom, validTo, note }` · `{ action: "return", note }` · `{ action: "cancel" }` · `{ action: "extend", deadline }` — ตรวจสถานะต้นทางถูกต้อง (ดู 4) มิฉะนั้น 409 |
| `GET /api/rfq/[id]/xlsx` | Excel เลย์เอาต์เดิม 1 ชีตต่อระบบ (exceljs โหลดตอนเรียก) |
| `GET /api/rfq/[id]/log` | ประวัติ |
| `GET /api/rfq/catalog` | แคตตาล็อกรุ่นล่าสุด (ใช้ใน modal สร้างลิงก์แสดงชื่อชีต/จำนวนงาน) |

### 3.2 ฝั่งอู่ (public · ไม่มี session)

| หน้า | ทำอะไร |
|---|---|
| `/q/[token]` | **หน้าหลัก**: ยืนยันตัวตน (ครั้งแรก) → การ์ด 2 ใบ **ค่าแรง** / **อะไหล่** แสดงความคืบหน้าแต่ละส่วน + ปุ่ม **ส่งใบเสนอราคา** (ต้องติ๊กยอมรับว่างานที่ว่าง = ไม่เสนอ) |
| `/q/[token]/labour` | หน้าค่าแรง: wizard ชีตละขั้น การ์ดละงาน (รายละเอียดด้านล่าง) · ปุ่มกลับหน้าหลัก |
| `/q/[token]/parts` | หน้าอะไหล่: wizard ชีตละขั้น รายการละแถวกะทัดรัด: ชื่อ/SKU/หน่วย/ใช้กับ · ฿/หน่วย L, S (+ "S เหมือน L") · ยี่ห้อ/สเปก · รับประกัน (เดือน) · ส่งมอบ (วัน) · หมายเหตุ · ปุ่ม "ไม่มีจำหน่าย" · ค้นหาในชีต · บันทึกอัตโนมัติเหมือนค่าแรง |

- **ขั้นยืนยันตัวตน**: แสดงชื่ออู่ตัวใหญ่ + "ใบขอราคาจาก Mena Transport · ปิดรับ DD/MM" · ช่อง ชื่อผู้ติดต่อ, เบอร์โทร, อีเมล (กรอกอย่างน้อย 1 ใน 2), checkbox "ยืนยันว่าเสนอราคาในนาม <ชื่ออู่>" · กดต่อ → บันทึก contact
- **ขั้นชีต**: หัวชีต + ความคืบหน้า "กรอกแล้ว 3/28" · งานละ 1 การ์ด: ชื่องาน, ขอบเขต (พับ/กางได้), เกณฑ์ เบา/กลาง/หนัก (พับ), ชม.อ้างอิง L/S · ตัวเลือก 3 ปุ่ม **รายชั่วโมง / เหมา / ไม่รับงานนี้** · รายชั่วโมง = อัตรา ฿/ชม. + ชม.มาตรฐาน · เหมา = เบา/กลาง/หนัก · บล็อก Mixer L แล้ว Mixer S พร้อมสวิตช์ "S เหมือน L" · รับประกัน (เดือน) + หมายเหตุ · ทุกช่องเป็น `inputmode="decimal"` ตัวเลขล้วน · **บันทึกอัตโนมัติ** เมื่อออกจากช่อง (PATCH ทีละงาน) มีป้าย "บันทึกแล้ว HH:MM" / "บันทึกไม่สำเร็จ ลองใหม่"
- **ส่งจากหน้าหลัก**: การ์ดแต่ละส่วนแสดง "กรอกแล้ว n/N" งานที่ยังว่างขึ้นสีเหลืองในหน้าส่วนนั้น (ส่งได้ทั้งที่ยังว่าง — อู่ไม่จำเป็นต้องเสนอทุกงาน แต่ต้องกดยืนยันว่า "งานที่ว่างไว้ = ไม่เสนอราคา") · หมายเหตุท้ายใบ · ปุ่ม **ส่งใบเสนอราคา**
- **หลังส่ง**: หน้าขอบคุณ + สรุปที่ส่ง · เปิดลิงก์ซ้ำเห็นหน้านี้ (อ่านอย่างเดียว) จนกว่าจัดซื้อจะส่งกลับแก้
- **สถานะพิเศษ**: หมดอายุ → "ลิงก์นี้ปิดรับแล้ว ติดต่อจัดซื้อ" · ยกเลิก → "ลิงก์นี้ถูกยกเลิก" · ส่งกลับแก้ → แถบสีส้มแสดง returnNote ด้านบนฟอร์ม
- มือถือก่อน: การ์ดเต็มความกว้าง ปุ่มสูง ≥44px ฟอนต์ Mitr ตามหน้าอื่น · ไม่โหลด exceljs/pdf · ไม่ใช้ sidebar ของแอป (layout แยก)

API public:

| Method · path | ทำอะไร |
|---|---|
| `GET /api/q/[token]` | ใบ + งานในแคตตาล็อก (ตัด confirm/createdBy ออก) · บันทึก openedAt ครั้งแรก + log open · สถานะ สร้างแล้ว → กำลังกรอก เมื่อมี contact แล้ว |
| `PATCH /api/q/[token]` | `{ contact }` หรือ `{ items: { [jobCode]: RfqAnswer } }` หรือ `{ parts: { [key]: RfqPartAnswer } }` (≤ 20 รายการต่อครั้ง) · รับเฉพาะสถานะ กำลังกรอก/สร้างแล้ว/ส่งกลับแก้ และยังไม่พ้น deadline · ตรวจ jobCode ∈ ชีตที่ให้ · ตัวเลข ≥ 0 |
| `POST /api/q/[token]/submit` | `{ submitNote, acknowledgeBlank: true }` → ส่งแล้ว + submittedAt + log · 409 ถ้าสถานะไม่ถูก/ไม่มี contact |

middleware.ts: ปล่อย `pathname.startsWith("/q/")` และ `pathname.startsWith("/api/q/")` ผ่านโดยไม่ตรวจ cookie
(ทั้งสองอย่างเช็ค token ในตัวเอง — token ผิด = 404 ไม่บอกว่ามี/ไม่มี)

## 4. สถานะและการเปลี่ยน (ตรวจฝั่ง server ทุกครั้ง)

```
สร้างแล้ว ──(อู่กรอก contact)──▶ กำลังกรอก ──(อู่ submit)──▶ ส่งแล้ว ──(จัดซื้อ confirm)──▶ ยืนยันแล้ว
   │                                 │                          │
   │                                 │                          └─(จัดซื้อ return + เหตุผล)─▶ ส่งกลับแก้ ──(อู่ submit)──▶ ส่งแล้ว
   └────────────(จัดซื้อ cancel ได้จากทุกสถานะยกเว้น ยืนยันแล้ว)────────────────────────────▶ ยกเลิก
```
- **หมดอายุ** = deadline ผ่านแล้ว และสถานะยังเป็น สร้างแล้ว/กำลังกรอก/ส่งกลับแก้ → อู่เขียนไม่ได้ จัดซื้อกด "ต่ออายุ" (extend) แล้วกรอกต่อได้
- ยืนยันแล้ว = ล็อกทั้งสองฝั่ง (แก้ไม่ได้ทั้ง items และ contact) — ถ้าต้องแก้ ให้สร้างลิงก์ใหม่ (ประวัติราคาเดิมคงอยู่)
- validTo ผ่านแล้ว → หน้า /rfq แสดงป้าย "ราคาหมดอายุ" (ไม่เปลี่ยนสถานะ)
- confirm/cancel ต้อง isAdmin · create/return/extend = ทุกคนที่ login

## 5. ความปลอดภัยของลิงก์สาธารณะ

- token 18 ไบต์สุ่ม (144 บิต) เดาไม่ได้ · เก็บตรง ๆ ใน DB (เทียบเท่าลิงก์เชิญทั่วไป; ถ้าจะยกระดับภายหลังเก็บ hash แทน)
- ทุก API public ตรวจ token + สถานะ + deadline ก่อนเขียน · เขียนได้เฉพาะ contact/items/submit — ไม่มีทางแก้ vendor/sheets/deadline จากฝั่งอู่
- ขนาด body จำกัด (items ≤ 20 งาน/ครั้ง, note ≤ 500 ตัวอักษร, ตัวเลข 0–9,999,999)
- ไม่มี rate-limit ตาม IP ในรอบนี้ (ไม่มี KV) — ความเสี่ยงคือ spam เขียน items ของใบตัวเอง ซึ่งกระทบแค่ใบนั้น
- ไม่ใส่ข้อมูลภายใน (ราคาเก่า/ราคากลาง/ชื่ออู่อื่น) ในหน้า public เด็ดขาด — กัน anchoring ตามกฎ RFQ เดิม

## 6. Export Excel

`GET /api/rfq/[id]/xlsx` สร้างไฟล์ 1 ชีตต่อระบบที่ให้ เลย์เอาต์เดียวกับฟอร์มต้นฉบับ (หัวใบ ผู้เสนอราคา = ชื่ออู่ + ผู้ติดต่อ,
หัวตาราง 3 ชั้น L/S × รายชั่วโมง/เหมา, 19 คอลัมน์) เติมค่าที่อู่กรอก · งาน skip เขียน "ไม่รับงาน" ในหมายเหตุ ·
ชื่อไฟล์ `ใบเสนอราคา_<อู่>_<รอบ>.xlsx` · ใช้ exceljs ที่มีอยู่แล้ว (โหลดตอนเรียก)

## 9. สมมติฐานที่ใช้ (แก้ได้ตอน review)

- 1 ลิงก์ = 1 อู่ = 1 รอบ · อู่เดิมขอรอบใหม่ = ลิงก์ใหม่ (ราคาเก่าไม่หาย)
- วันปิดรับค่าตั้งต้น 14 วัน · ราคามีผลค่าตั้งต้น 12 เดือนนับจากวันยืนยัน
- อู่ส่งได้แม้กรอกไม่ครบ (งานที่ว่าง = ไม่เสนอ) แต่ต้องมี contact และติ๊กยอมรับ
- ยืนยัน/ยกเลิก = แอดมิน (เหมือนสถานะอนุมัติอู่) · สร้างลิงก์/ส่งกลับแก้ = ทุกคนที่ login
- ค่าแรงและอะไหล่อยู่คนละหน้าในลิงก์เดียว ส่งครั้งเดียวจากหน้าหลัก (ผู้ใช้เลือก 2026-09-10)
