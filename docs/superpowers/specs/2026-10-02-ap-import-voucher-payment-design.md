# /ap-tracking — นำเข้าการตั้งเบิก (บัญชี) + นำเข้าการจ่าย (การเงิน)

วันที่: 2026-10-02 · ผู้สั่ง: Plug (narongkorn.a) · รีวิวผ่านตัวทดสอบอ่านอย่างเดียวบน localhost ก่อนทำจริง (01/10/2026)

## ลำดับงาน
ปุ่มเรียงตามขั้น: **นำเข้าการตั้งเบิก [บัญชี]** → **นำเข้าการจ่าย [การเงิน]** — ป้ายฝ่ายบอกว่าใครนำเข้า
(สิทธิ์ไม่เปลี่ยน: ตั้งเบิก = `isAccounting` · การจ่าย = `canImportPayment` เหมือนปุ่มเดิม)
ต้องนำเข้าตั้งเบิกก่อน — ไฟล์จ่ายไม่มีเลข DD ต้องโยงผ่านเลข Voucher ที่การตั้งเบิกบันทึกไว้

## นำเข้าการตั้งเบิก — ไฟล์ "รายงานตั้งเจ้าหนี้อื่นๆ"
- อ่านในเบราว์เซอร์ (`lib/ap-voucher-import.ts`) หาคอลัมน์จากชื่อหัว: `DocuNo` `DocuDate` `GoodRemark` `empname`
- ใช้เฉพาะแถว `empname` ขึ้นต้น **อาทิติยา / วราพร** (ชื่อจริงมีช่องว่างคู่)
- เลข DD จาก `GoodRemark` = `(KK|LB|SB)DD` + 8 หลักพอดี · ตัวที่หน้าตาเหมือนแต่ผิดรูปแบบ (7/9 หลัก, DDD, KDD) → กลุ่ม "อ่านเลข DD ไม่ได้" ไม่เดาแก้
- เลขที่ Voucher/ตั้งหนี้ = `DocuNo` (DD เดียวมีได้หลายเลข)
- ผล (`/api/ap-tracking/voucher-import`, dryRun ก่อนเสมอ):
  - **ส่งบัญชีแล้ว + พบในไฟล์ → ผ่าน + เติม voucherNos** · **ไม่คิดกำหนดจ่าย** (บัญชีกำหนดทีหลังทีละใบ)
  - ผ่าน/จ่ายแล้ว → ไม่โชว์ ไม่แตะ · ยังไม่ส่งบัญชี / ไม่ผ่านอยู่ / ก่อนปี 69 → โชว์ แต่ข้าม
  - **ส่งบัญชีแล้วแต่ไม่พบในไฟล์** → บัญชีตอบในเว็บ: **ไม่ผ่าน** (PATCH review + เหตุผล) หรือ **รอรอบเครดิตถัดไป** (PATCH `nextRound` = ป้าย ใบยังอยู่ขั้นเดิม ล้างเองเมื่อผ่าน/ไม่ผ่าน)
- เขียนด้วย filter "ยังส่งบัญชีแล้วและยังไม่ตรวจ" กันทับผลที่บัญชีเพิ่งกดระหว่างพรีวิว · ลง log `field: review` ทุกใบ

## กำหนดวันจ่ายทีหลัง
- PATCH `/api/ap-tracking/[code]` `{ setPay: true, payType, payCreditTerm?, payDate?, payDateManual? }` — เฉพาะใบ ผ่าน ที่ยังไม่มี `pay`
- ตรรกะคิดวันจ่ายยกออกมาเป็น `payOnPass()` ใช้ร่วมกับการกดผ่านปกติ (สูตรเดียวกัน) · วันตั้งต้น = วันที่กดกำหนด
- หน้าใบ แท็บการเงิน: กล่อง "⚠️ ผ่านแล้ว แต่ยังไม่กำหนดวันจ่าย" + ปุ่ม 📅 → กล่องยืนยันเดิมโหมด setPay

## นำเข้าการจ่าย — ไฟล์ "รายงานจ่ายชำระเจ้าหนี้"
- ตรวจรูปแบบจากหัวคอลัมน์ (`DocuNo` `DocuDate` `DocuNo_inv` `PayAmnt`) — ไม่ใช่ → ส่งต่อไดอะล็อกใบปะหน้ารอบโอนแบบเดิม (ไฟล์เดิมยังใช้ได้)
- หัวคอลัมน์ซ้ำในไฟล์จริง (`DocuDate` ×2) → ใช้ตัวแรก (= วันจ่าย PV)
- PV = `DocuNo` · วันจ่าย = `DocuDate` (หลายงวด = ล่าสุด) · โยงใบ DD: `DocuNo_inv` → `ap_tracking.voucherNos` ∪ เลข DD ใน `InvNo`
- ผล (`/api/ap-tracking/payment-import`):
  - ผ่าน → **จ่ายแล้ว** (`paid` = PV/วันจ่าย/source `payment-report`)
  - **จ่ายก่อนผ่าน** (ยังไม่ผ่าน) → จ่ายแล้ว + `paid.beforePass = true` (ป้ายในตาราง/หน้าใบ)
  - จ่ายแล้วจากรอบโอน (ไม่มี PV) / PV งวดใหม่ → เติม PV แบบ dotted path ไม่ทับข้อมูลรอบเดิม
  - ไม่มี tracking → สร้างให้ ยกเว้นคลังตระกูลสระบุรี (กติกา 21/08/2026) · ไม่ผ่านอยู่ / ก่อนปี 69 → ข้าม
  - เลขตั้งหนี้ครอบหลายใบ → เก็บ PV/วันจ่าย ไม่ใส่ยอด (เก็บ `sharedWith`)

## หน้าจอ (ทั้งสองไดอะล็อก)
แท็บตามกลุ่ม · ชิปเดือนจากเลข DD (4 หลักหลัง DD: 2601 = ม.ค. 69) · มุมมองสรุปรายเดือน (คลิกเลขเปิดรายการ)
· Export Excel (ชีตสรุป + 1 ชีตต่อกลุ่ม · ชีตไม่พบในไฟล์มีช่องให้บัญชีกรอกคำตอบ) · ซ่อนใบที่ไม่ต้องทำอะไร โชว์แค่จำนวน

- E2E กับสำเนาข้อมูลจริงบน Mongo local (ไฟล์จริงทั้งสอง): ตั้งเบิกผ่าน 86 · ไม่พบในไฟล์ 229 · จ่ายแล้ว 1,180 (รวมจ่ายก่อนผ่าน 6 · เติม PV 96 · สร้างใหม่ 4) · รันซ้ำไม่เขียนซ้ำ · production ไม่ถูกแตะ
