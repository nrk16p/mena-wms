## ทำไมต้องมี

เจ้าหนี้ถามสถานะบิลผ่านไลน์บ่อย ทุกครั้งคนในทีมต้องเปิด `/ap-tracking` หาใบแล้วพิมพ์ตอบ
ลิงก์นี้ให้เจ้าหนี้ล็อกอินเข้าไปดูเองว่าบิลถึงไหน จะได้เงินวันไหน ไม่ต้องรอใครตอบ

## เป้าหมาย

1. หน้า `/vendor-portal/login` และ `/vendor-portal` แบบมือถือก่อน ใช้บนคอมได้ด้วย
2. เห็นใบ DD ของเจ้าตัวเองเท่านั้น ช่วง **ต้นเดือนที่แล้ว 5 เดือน ถึงวันนี้** ตามวันรับของ
   (วันนี้ 27 ต.ค. 69 = 1 พ.ค. – 27 ต.ค. 69) คิดตามเวลาไทย *(การตีความ "6 เดือน" เป็นของผม)*
   **บวกใบ "รอโอน"** ที่รับของก่อนช่วงนี้ (ย้อนถึง `AP_GO_LIVE`, ไม่เกิน 12 เดือน) — ใบเครดิตยาวที่รับของต้นช่วงอาจโอนหลังหลุดช่วงไปแล้ว
   *(ของผม)* · ใบเก่าที่ยังค้างขั้นภายในไม่โชว์ เพราะใบยุค Excel ก่อน ส.ค. 69 หลายใบไม่มีหลักฐานจ่ายในระบบ (รีวิวท้าย branch)
   · กติกาเดียวกันใช้กับด่าน 404 ของรายการสินค้า
3. 3 สถานะ (ดูหัวข้อสถานะ) + กล่อง "รอบโอนถัดไป" บอกวัน จำนวนใบ ยอดเงิน
4. ค้นหาช่องเดียว: เลข DD · เบอร์รถ · ทะเบียน · เลขใบแจ้งหนี้ของร้าน (`supplier_ref_no`) *(อันหลังผมเพิ่มเอง)*
5. กรอง: สถานะ (เลือกหลายอัน) · เดือนที่รับของ / ช่วงวันที่ · เรียง (รับของล่าสุด / กำหนดโอนใกล้สุด / ยอดมากสุด)
   แถบสถานะด้านบนแตะกรองเร็วได้ · ช่องค้นกับปุ่มกรองติดบนจอตอนเลื่อน
6. ปุ่มคัดลอกเลข DD รายใบ (เปลี่ยนเป็นเครื่องหมายถูก + toast) และปุ่ม "คัดลอก DD ทั้งหมด"
   ที่คัดลอกเฉพาะใบที่กรองอยู่ บรรทัดละเลข
7. แตะ "รายการสินค้า N รายการ" ใต้แต่ละใบ → เปิดดูชื่อสินค้า รหัส จำนวน หน่วย ราคาต่อหน่วย ยอดรวม
   และท้ายใบ รวมก่อน VAT · VAT · รวมทั้งสิ้น (โหลดตอนแตะ ไม่โหลดทุกใบล่วงหน้า)
8. บัญชีเจ้าหนี้สร้างและรีเซ็ตจากหน้า WMS โดยคนที่มีสิทธิ์แก้ในส่วน `ap`

## ไม่ทำรอบนี้

- เจ้าหนี้แก้ข้อมูล อัปโหลดไฟล์ หรือส่งเอกสารผ่านพอร์ทัล — ดูอย่างเดียว
- สมัครเอง · เปลี่ยนรหัสเอง · ลืมรหัสแบบอัตโนมัติ (ลืมรหัส = ติดต่อจัดซื้อให้รีเซ็ต) *(ของผม)*
- ส่งไลน์หรืออีเมลหาเจ้าหนี้อัตโนมัติ
- ตัวกรองสาขา

## ห้ามเกิด (ถึงจะใช้งานได้ก็ถือว่าพัง)

- เจ้าหนี้เห็นใบหรือรายการสินค้าของเจ้าอื่น ไม่ว่าจะเดา URL หรือแก้ request
- cookie ของเจ้าหนี้ใช้เข้าหน้าหรือ API ภายในได้
- ข้อมูลภายในหลุดไปถึงเบราว์เซอร์เจ้าหนี้ — **ต้องตัดที่ API ด้วย whitelist field** ไม่ใช่แค่ซ่อนใน UI
- เก็บรหัสผ่านแบบอ่านกลับได้

## สถานะที่เจ้าหนี้เห็น

ใช้ข้อมูลเดียวกับ `apStage()` ใน `lib/ap-tracking.ts` แต่**ลำดับต่างกัน** — ฝั่งภายใน "ไม่ผ่าน" ชนะทุกขั้น
ฝั่งเจ้าหนี้ "จ่ายแล้ว" ต้องชนะ (เงินถึงมือเขาแล้ว)

| ลำดับตรวจ | เงื่อนไข | เจ้าหนี้เห็น | วันที่ที่โชว์ |
|---|---|---|---|
| 1 | `apPaidConfirmed(paid)` | **โอนแล้ว** | `paid.date` (ถ้าไม่มี โชว์แค่สถานะ) |
| 2 | `review.status === "ผ่าน"` | **รอโอน** | `pay.payDate` กำหนดโอน · ถ้า payDate < วันนี้ ขึ้น "ครบกำหนดโอน … · รอยืนยันยอดโอน" |
| 3 | อย่างอื่นทั้งหมด (รอประกบ · ครบชุด · ส่งบัญชีแล้ว · ไม่ผ่าน) | **กำลังดำเนินการ** | — |

กล่องรอบโอนถัดไป = ใบ "รอโอน" ที่ `pay.payDate` ≥ วันนี้ เอาวันที่น้อยสุด รวมจำนวนใบและยอดของวันนั้น
ไม่มีใบรอโอน = ไม่โชว์กล่อง

## ข้อมูล

### รายการใบ — `GET /api/vendor-portal/bills`

- ใช้แหล่งและการ enrich เดียวกับ `GET /api/ap-tracking` โหมดเจ้าเดียว (`?supplier=&year=`):
  `atms.deposit_header` match `supplier` ∈ ชื่อของเจ้านี้ + ตัดแถวคืนสต๊อกภายใน (`$nor supplier "" purchase_order ""`)
  + join `ap_tracking` (review / pay / paid) + PO (`ยานพาหนะ` → ทะเบียน, `fleetByPlate` → เบอร์รถ)
  ห้ามยิง HTTP หากันเอง · พอร์ทัลมีคิวรีของตัวเองใน `lib/vendor-portal-db.ts` (ดึงแค่ field ที่ต้องใช้) โดยใช้ join ชุดเดียวกัน
  *(ตอนวางแผนตัดสินใจไม่แตะ `app/api/ap-tracking/route.ts` — ไฟล์ใหญ่ที่ session อื่นแก้อยู่บ่อย การแยกออกมาเสี่ยงชนกันมากกว่าได้)*
- ช่วงวันใช้ `received_at` ตามข้อ 2 ของเป้าหมาย (ข้ามปีได้ เช่นเปิดเดือน ม.ค.)
- ตัดคลังตระกูลสระบุรีทิ้ง — กติกาเดียวกับ `isSaraburi` ใน `app/api/ap-tracking/payment-import/route.ts`
  (`warehouse` มี "สระบุรี" และไม่มี "DIST") ย้ายไป lib แล้วใช้ร่วมกัน
- ยอดเงิน = `apNetOf()` (รวม VAT) ตรงกับที่ /ap-tracking โชว์
- **field ที่ส่งออกได้เท่านั้น:** `depositCode` · `receivedAt` · `supplierRefNo` · `vehicle` · `fleetNo` ·
  `amount` · `status` (`processing|scheduled|paid`) · `payDate?` · `paidDate?` · `itemCount`
  (ถ้านับได้ถูก ถ้าไม่คุ้มให้ตัดออกแล้วป้ายเขียนแค่ "รายการสินค้า")
- ห้ามส่ง: ชื่อคน อีเมล log หมายเหตุ เหตุผลตีกลับ วันที่ส่งบัญชี เลข PV เลขตั้งหนี้ ไฟล์แนบ
  สถานะเอกสารครบชุด เครดิตเทอมรายใบ ชื่อคลัง

### รายการสินค้า — `GET /api/vendor-portal/bills/[code]/items`

- ตรวจก่อนว่า DD นี้เป็นของเจ้าที่ล็อกอินและอยู่ในช่วง 6 เดือน ไม่ใช่ = ตอบ 404 เหมือนหาไม่เจอ
- อ่าน `atms.deposit_items` ของใบนั้น (ดูชื่อ field และการแยก "รหัส : ชื่อ" ได้จาก `app/api/ap-tracking/[code]/route.ts`
  กับ `apItemKeys`) ส่งออก: ชื่อ · รหัส · จำนวน · หน่วย · ราคาต่อหน่วย · ยอดรวม
- ท้ายใบ: รวมก่อน VAT · VAT · รวมทั้งสิ้น จาก `apGrossOf/apVatOf/apNetOf` ของหัวใบ
- ถ้า `apItemVerification(items, header.amount)` ไม่ผ่าน (รายการสินค้าใน Mongo ตามหัวใบไม่ทัน)
  → ไม่ส่งรายการ ส่ง `pending: true` แทน หน้าเว็บขึ้น "รายการสินค้ากำลังอัปเดต ลองดูใหม่ภายหลัง"
  *(ของผม — กันเจ้าหนี้เห็นตัวเลขที่บวกไม่ตรงยอด)*

## บัญชีผู้ใช้

### เก็บที่ไหน

collection ใหม่ `master_data.vendor_portal_accounts` (unique index `username`)

| field | ความหมาย |
|---|---|
| `username` | รหัสผู้ขาย ATMS (`ap_supplier.atmsCode`) ตัดช่องว่าง + ตัวพิมพ์ใหญ่ ล็อกอินพิมพ์เล็ก/ใหญ่ได้ |
| `atmsCode` | รหัสตามที่เก็บใน ap_supplier |
| `displayName` | ชื่อที่โชว์หัวหน้า (ชื่อแรกของเจ้านี้) |
| `passwordHash` | `scrypt$<salt>$<hash>` ใช้ `node:crypto` scrypt + `timingSafeEqual` ไม่ต้องลง package |
| `passwordSetAt` / `passwordSetBy` | ออกรหัสล่าสุดเมื่อไหร่ ใครกด |
| `tokenVersion` | เพิ่มทุกครั้งที่รีเซ็ตรหัสหรือปิดบัญชี → session เก่าหลุดทันที |
| `disabled` | ปิดบัญชี |
| `failedCount` / `lockedUntil` | ผิด 5 ครั้งติด ล็อก 15 นาที |
| `lastLoginAt` / `loginCount` | ไว้ดูว่าเจ้าไหนใช้จริง |
| `createdAt` / `createdBy` | |

- ชื่อเจ้าหนี้ที่บัญชีครอบ **หาสดทุก request** = ทุกแถว `ap_supplier` ที่ `atmsCode` ตรงกัน
  (รหัสเดียวมีหลายชื่อได้ → บัญชีเดียวเห็นครบทุกชื่อ · ชื่อใหม่ที่ sync เข้ามาทีหลังก็ติดมาเอง)
- เจ้าที่ไม่มี `atmsCode` สร้างบัญชีไม่ได้ ปุ่มขึ้น "ไม่มีรหัสผู้ขาย"
- **ชื่อซ้ำหลายรหัส:** `deposit_header.supplier` เป็นแค่ชื่อ และ `scripts/sync-ap-suppliers-from-atms.mjs` เลือกรหัสเดียวเมื่อชื่อซ้ำใน ATMS
  (`byName`) → ชื่อที่ใน `atms.supplier_master` มีมากกว่า 1 รหัส **ไม่ขึ้นในพอร์ทัลของใครเลย** และหน้าจัดการขึ้นเตือน
  "ชื่อนี้ซ้ำกับเจ้าอื่นใน ATMS ใบของชื่อนี้ไม่ขึ้นในพอร์ทัล" *(ของผม — กันเจ้าหนึ่งเห็นบิลอีกเจ้า)*
- `ap_supplier` อัปเดตด้วยสคริปต์ที่รันมือ (ไม่มี cron) ชื่อใหม่ใน ATMS จะติดบัญชีก็ต่อเมื่อรันสคริปต์นั้นแล้ว — รอบนี้ไม่ทำ sync อัตโนมัติ
- ไม่สร้างให้ชื่อที่ขึ้นต้นด้วย "เงินสด" (ไม่ใช่ร้านจริง เป็นถังรวมซื้อเงินสด) และตัดชื่อเงินสดออกจากชุดชื่อที่ใช้ดึงใบทุก request ด้วย

### รหัสผ่าน

- สุ่ม 10 ตัวด้วย `crypto.randomInt` จากตัวอักษรที่ไม่สับสน (ไม่มี 0 O o 1 l I)
- **โชว์ครั้งเดียวตอนสร้าง/รีเซ็ต** แล้วเก็บแค่ hash — หายหรือลืม = กดรีเซ็ตออกรหัสใหม่ *(ของผม แทนการเก็บรหัสไว้เปิดดูซ้ำ)*

### หน้าจัดการใน WMS

อยู่ในหน้า `/ap-tracking/suppliers` เดิม (รายชื่อเจ้าหนี้ที่มีอยู่แล้ว) เพิ่มคอลัมน์ "บัญชีเจ้าหนี้":
ยังไม่มี · มีแล้ว (เข้าล่าสุด วว/ดด) · ปิดอยู่

- ปุ่มรายแถว: **สร้างบัญชี** / **รีเซ็ตรหัส** / **ปิด–เปิดบัญชี**
- สร้างหรือรีเซ็ตแล้วขึ้นกล่องโชว์ชื่อผู้ใช้ + รหัส + ปุ่ม "คัดลอกข้อความส่งไลน์" ข้อความตัวอย่าง:

  ```
  ลิงก์ดูสถานะบิลกับวันโอนเงินของร้านครับ
  https://mena-wms.vercel.app/vendor-portal
  ชื่อผู้ใช้ VEN-00008
  รหัสผ่าน Kp7xR2mQa9
  ```

- ปุ่ม **สร้างให้ทุกเจ้าที่ยังไม่มี** = ทุกเจ้าที่มี `atmsCode` + มีใบ DD ในช่วง 6 เดือน + ไม่ใช่เงินสด
  → ยืนยันก่อน (บอกจำนวนเจ้า) → สร้าง → กล่องตารางรหัสทั้งหมด + ดาวน์โหลด Excel
  (รหัสคู่ค้า · ชื่อ · ชื่อผู้ใช้ · รหัสผ่าน · ลิงก์) ปิดกล่องแล้วเปิดดูรหัสอีกไม่ได้
- API อยู่ใต้ `/api/ap-suppliers/portal-accounts…` เพื่อให้ policy ส่วน `ap` ใน middleware คุมให้เอง
  (`view` = เห็นสถานะบัญชี · `edit` = สร้าง/รีเซ็ต/ปิด) — ไม่ต้องเพิ่มกติกาสิทธิ์ใหม่

## การล็อกอินและ session

- `POST /api/vendor-portal/login` `{username, password}` → cookie `vp_session`
  (httpOnly · Secure บน https · SameSite=Lax · path `/` · อายุ 7 วัน) = JWT HS256 ด้วย `jose` (มีใน node_modules แล้ว
  ผ่าน next-auth — ถ้าจะ import ตรงให้ใส่ใน package.json ด้วย)
- กุญแจเซ็น = HMAC-SHA256(`NEXTAUTH_SECRET`, `"vendor-portal-v1"`) → **ไม่ต้องตั้ง env ใหม่บน Vercel**
- claims: `sub` = username · `tv` = tokenVersion
- ทุก API ของพอร์ทัล: ตรวจ JWT → โหลดบัญชี → ต้องไม่ `disabled` และ `tv` ตรง ไม่ผ่าน = 401 แล้วหน้าเว็บพาไปล็อกอิน
- ล็อกอินผิดตอบข้อความเดียวเสมอ "ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง" (ไม่บอกว่าผิดชื่อหรือผิดรหัส) ·
  ถูกล็อกอยู่ตอบ "ลองผิดหลายครั้ง รอ 15 นาทีแล้วลองใหม่"
- `POST /api/vendor-portal/logout` ล้าง cookie

## middleware และ app shell

- `middleware.ts`: ปล่อย `/vendor-portal`, `/vendor-portal/…`, `/api/vendor-portal/…` ผ่านก่อนเช็ค session
  แบบเดียวกับ `/q/` — **เทียบ path แบบเต็มคำ** (`=== "/vendor-portal"` หรือขึ้นต้น `"/vendor-portal/"`)
  ห้ามใช้ `startsWith("/vendor")` เพราะจะเปิด `/vendors` ให้คนนอก
- `vp_session` ไม่มีความหมายกับ route อื่นเลย (middleware ภายในยังเช็ค cookie next-auth เหมือนเดิม)
- `components/app-shell.tsx`: หน้า `/vendor-portal…` ไม่มี sidebar/navbar/SessionGuard เหมือน `/q/`
- หน้าเจ้าหนี้เรียกได้แค่ `/api/vendor-portal/*`
