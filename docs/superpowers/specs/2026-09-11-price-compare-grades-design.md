# ใบเทียบราคา — เกรดเป็นแถวย่อยของรายการ — Design

วันที่: 2026-09-11 · สถานะ: รอผู้ใช้ ok · ต่อยอด v2 (`2026-09-10-price-compare-v2-design.md`)

## ที่มา (ผู้ใช้ตอบ 2026-09-11)
- "+เกรด อิงตามรายการ" = **แถวย่อยของรายการ**: ชื่อเกรด (เช่น มือ 1 / มือ 2 / ซ่อมของเดิม) ใช้ร่วมกันทุกเจ้า แต่ละเจ้ากรอกราคาต่อเกรด แต่ละรายการเลือก 1 เกรด + 1 เจ้า
- ยอดรวม **นับเฉพาะเกรดที่เลือก**

## Data model (แถวแบน + group key — ไม่เปลี่ยนรูป prices / lineSupplier)
```ts
PcItem = { name; qty; unit; sku?; group?: string; grade?: string }
```
- แต่ละ **เกรด = 1 แถวใน items** (จึงมีราคาต่อเจ้า `prices[i]` และ `lineSupplier[i]` ของตัวเองตามเดิม — invariant `items.length === prices.length === lineSupplier.length` คงเดิม)
- แถวที่อยู่รายการเดียวกันมี `group` เดียวกัน (id สุ่มสั้น เช่น `g-k3x9`) และต้อง **อยู่ติดกัน**; `grade` = ชื่อเกรดของแถวนั้น
- รายการธรรมดา = ไม่มี `group` (กลุ่มขนาด 1) — เอกสาร v1/v2 เดิมทุกใบใช้ได้ทันที ไม่ต้อง migrate
- ชื่อ/จำนวน/หน่วย/sku เป็นของทั้งกลุ่ม: normalizeDoc คัดลอกค่าจากแถวแรกของกลุ่มไปทุกแถว (กันข้อมูลแตก)

## กติกาการนับ ("แถวที่นับ")
- กลุ่มขนาด 1 → แถวนั้นนับ
- กลุ่มหลายเกรด → นับ **เฉพาะแถวที่มี `lineSupplier`** (เกรดที่เลือก); ยังไม่เลือก = กลุ่มค้าง (ไม่นับ + isComplete ไม่ผ่าน "ยังไม่เลือกเกรด: <ชื่อรายการ>")
- ในกลุ่มหนึ่งเลือกได้ **ไม่เกิน 1 แถว** (validateDoc)
- **เอกสารที่มีรายการหลายเกรดอย่างน้อย 1 รายการ = โหมดเลือกรายบรรทัดทั้งใบ** (ซ่อนการเลือกทั้งใบ, `selectedSupplier` = null) — กันโหมดผสมครึ่งๆ กลางๆ

## ฟังก์ชัน (lib/price-compare.ts — pure)
- ใหม่: `groupsOf(doc)` → `{ key, rows: number[] }[]` ตามลำดับ; `countedRows(doc)` → boolean[]; `hasGrades(doc)`; `newGroupId()` (ไม่ import — ใช้ Math.random)
- `supplierTotals` / `lowestNet` / `completeSupplierCount`: คิดจากแถวที่นับ (เจ้าที่ "ครบ" = เสนอราคาอย่างน้อย 1 เกรดของทุกรายการ)
- `pickLowestPerLine`: ต่อ **กลุ่ม** เลือกคู่ (เกรด, เจ้า) ที่สุทธิหลัง VAT ต่ำสุด → คืน lineSupplier ที่แถวอื่นในกลุ่มเป็น null (ใช้กับปุ่ม "เลือกถูกสุดทุกแถว", bestMixNet, และกฎเหตุผล — เทียบรายแถวแบบเดิมได้เลย)
- `allLinesAwarded`: ทุกกลุ่มมีแถวที่เลือกครบ 1 แถว
- `mixedTotals`: รวมเฉพาะแถวที่นับ; กลุ่มค้าง → null
- `validateDoc`: กลุ่มต้องติดกัน, เลือกได้ ≤1 แถวต่อกลุ่ม, กลุ่มหลายเกรดต้องมีชื่อเกรดทุกแถว
- `normalizeDoc`: รับ `group`/`grade`; sync ชื่อ/จำนวน/หน่วย/sku ในกลุ่ม; `hasGrades` → selectedSupplier = null

ตัวอย่างทดสอบ (Pump Rexroth 1 ตัว: มือ1 [—, 30,000, 30,000] · มือ2 [—, —, 25,000] · ซ่อมเดิม [21,000, —, —] + HYD/เกียร์/ค่าแรงเดิม): ถูกสุดต่อกลุ่ม = ซ่อมเดิม·S1, HYD·S2, เกียร์·S2, ค่าแรง·S3 → mixedTotals S1 22,470 · S2 2,996 · S3 5,350 → grand **30,816.00**; ถ้าเลือก มือ2·S3 แทน → grand 35,096.00, gap **4,280.00**

## UI (matrix)
- ปุ่ม "+เกรด" ในช่องรายการ: รายการธรรมดา → กลายเป็นกลุ่ม 2 เกรด (แถวเดิม + แถวใหม่ต่อท้าย ราคาว่าง); กลุ่มอยู่แล้ว → เพิ่มเกรดท้ายกลุ่ม
- กลุ่มหลายเกรดแสดงเป็น: **แถวหัวรายการ** (ลำดับ, SkuPicker ชื่อ, จำนวน, หน่วย, ลิงก์ราคากลาง, +เกรด, ลบทั้งรายการ, เลื่อนขึ้น/ลงทั้งกลุ่ม — ช่องราคาเว้นว่าง colSpan) แล้วตามด้วย **แถวเกรด** (`├ เกรด: [ช่องชื่อเกรด]`, ช่องราคาต่อเจ้า + radio, ลบเกรดนี้); ลบจนเหลือเกรดเดียว → กลับเป็นรายการธรรมดา (ลบ group/grade)
- radio ของทุกช่องในกลุ่มเป็นชุดเดียวกัน (เลือกช่องหนึ่ง = ล้างแถวอื่นในกลุ่ม)
- ลำดับเลขนับต่อรายการ (กลุ่ม) ไม่ใช่ต่อแถว
- ฟอร์ม §6: `hasGrades` → ซ่อนการเลือกทั้งใบ แสดง "มีรายการหลายเกรด — เลือกเกรดและเจ้ารายบรรทัด" + การ์ดยอดผสม; ถ้ามีกลุ่มค้าง แสดงรายชื่อ

## PDF
- แถวหัวรายการ: ลำดับ + ชื่อ + จำนวน + หน่วย (ช่องราคาเว้น); แถวเกรด: `├ เกรด: มือ 1` + ราคาต่อเจ้า, ✓ ที่เกรด+เจ้าที่เลือก; ยอดรวมทุกแถวคิดจากแถวที่นับ
- แถวหัวรายการกินโควตาแถวว่างเหมือนแถวรายการ (ยังหน้าเดียวสำหรับตัวอย่าง)

## Log / list
- log: เพิ่มสรุป "เกรด" เมื่อจำนวนแถวเกรดเปลี่ยน (`k → k' เกรด`); การเลือก (vector) ครอบคลุมการเปลี่ยนเกรดที่เลือกอยู่แล้ว
- list: ใช้ mixedTotals (group-aware) — ไม่ต้องแก้นอกจากทดสอบ

## ไม่ทำ
เรียงลำดับเกรดภายในกลุ่ม, เกรดต่างจำนวนกัน (qty ต่อเกรด), เกรดแยกต่อเจ้า
