# Deadstock — DD ที่ยังไม่ถูก WD ตัด (FIFO) คลังลาดกระบัง — Design

วันที่: 2026-08-14 · สถานะ: อนุมัติแนวทางแล้ว (รอ review spec)

## 1. ปัญหาและเป้าหมาย

คลังลาดกระบังสั่งซื้ออะไหล่เข้ามาด้วยใบรับสินค้า (DD) โดยส่วนใหญ่ระบุไว้ตั้งแต่ตอนขอซื้อว่า **ซื้อเพื่อรถคันไหน** แต่ของบางส่วนรับเข้ามาแล้ว **ไม่ถูกเบิกออกไปใส่รถ** (ไม่มีใบเบิก WD มาตัด) กลายเป็นทุนจมที่ไม่มีใครเห็น เพราะระบบเดิมไม่ได้ผูก DD กับ WD เป็นรายล็อต

**สิ่งที่มีอยู่แล้วและทำไมยังไม่พอ:**

| ของเดิม | ที่อยู่ | ทำอะไร | ทำไมไม่พอ |
|---|---|---|---|
| `dw_stockmovement` pipeline | `KPI-Motors/ext_WD_data` | กรอง `WD.notna()` แล้วสรุปยอดเบิก | **ทิ้งแถวที่ไม่มี WD ทั้งหมด** — คือด้านที่เราต้องการพอดี |
| `stock-onhand-kpi.ts` | mena-intelligence | `Σ(รับ−จ่าย)` สะสม = คงเหลือรวม | บอกยอดรวม แต่ไม่บอกว่าค้างมาจาก DD ใบไหน อายุเท่าไหร่ |
| `deadstock-kpi.ts` | mena-intelligence | ประมาณ dead stock จาก "ไม่เคลื่อนไหว ≥12 เดือน" | เป็น proxy — คอมเมนต์ในไฟล์เขียนยอมรับเองว่า *"ไม่มีอายุ lot จริง → ค่าเป็นตัวประมาณ"* |

**ไม่มีตรรกะ FIFO อยู่ที่ไหนเลยในทุกโปรเจกต์** (ตรวจด้วย grep ทั้ง `~/Documents/project`) — งานนี้คือการเขียนขึ้นใหม่

**เป้าหมาย:** หน้าเว็บใน mena-wms ที่จับคู่ใบรับ (DD) กับใบเบิก (WD) แบบ FIFO รายรหัสสินค้า เพื่อตอบ 3 คำถาม:
1. ภาพรายเดือนปี 2026 — ของค้างเพิ่มขึ้นหรือลดลง
2. ตอนนี้ DD ใบไหนยังไม่ถูกเบิก คงเหลือกี่ชิ้น มูลค่าเท่าไหร่
3. ค้างมากี่วัน — **โฟกัสที่เกิน 7 วัน**

> **หมายเหตุเรื่องชื่อ:** mena-intelligence มี KPI ชื่อ "deadstock" อยู่แล้วแต่**คนละนิยาม** (ของนั้น = ไม่เคลื่อนไหว ≥12 เดือน) คนละแอปจึงไม่ชนกันทางเทคนิค แต่ต้องระบุนิยามกำกับเสมอเวลาคุยข้ามทีม

## 2. โครงสร้างข้อมูลต้นทาง (ตรวจจากข้อมูลจริงแล้ว)

`atms.stockmovement_v5` — **DD กับ WD อยู่คนละแถว** ไม่ใช่แถวเดียวกัน:

| ประเภทแถว | DD | WD | รับ | จ่าย | ทะเบียน | หมายเหตุ |
|---|---|---|---|---|---|---|
| **รับเข้า** | `LBDD26060002` | `null` | 2 | `null` | **`null` เสมอ (0/2508)** | `LBPR26050758/71-5742/153/โม่ใหญ่` |
| **เบิกออก** | `null` | `LBWD26060003` | `null` | 2 | `สบ.71-4726` | `LBMR26050889...` |

ข้อเท็จจริงสำคัญ:
- ทุกแถวเป็น "รับ" หรือ "จ่าย" อย่างใดอย่างหนึ่งเสมอ ไม่มีแถวที่เป็นทั้งคู่หรือไม่เป็นอะไรเลย (17,867 + 36,202 = 54,069 พอดี)
- **แถว DD ไม่มีคอลัมน์ `ทะเบียน`** — ทะเบียนรถถูกฝังอยู่ใน `หมายเหตุ` แทน จึงต้องอ่านจาก `หมายเหตุ` เท่านั้น
- `วันที่` เป็น `Date` จริง, `year_month` เป็น string `"YYYY-MM"`

### Index — ข้อบังคับด้าน performance

```
year_month_1_inventory_id_1   ← ต้องใช้ตัวนี้
วันที่_1 · row_key_1 · row_hash_1 · _id_
```

**ไม่มี index บน `คลังสินค้า`** → ห้ามกรองด้วย `คลังสินค้า` เด็ดขาด (collscan 435k แถว) ต้องใช้ `inventory_id: "4"` ซึ่ง = คลังลาดกระบัง (ยืนยันด้วย `explain` แล้วว่าได้ `IXSCAN`)

| inventory_id | คลัง |
|---|---|
| **4** | **คลังลาดกระบัง** |
| 3 | คลังสระบุรี |
| 11 | คลังขอนแก่น |
| 24 | คลัง DIST |

## 3. กติกาคัดกรอง

จากแถวรับเข้าปี 2026 ทั้งหมด 17,867 แถว:

| ประเภท | แถว | มูลค่า | เอา |
|---|---|---|---|
| **มีทะเบียนรถใน `หมายเหตุ`** (ซื้อเพื่อรถคันนั้น) | **7,439** | ฿14.8M | ✅ **แสดง** |
| ไม่มีทะเบียน — `เข้าสต๊อกเพื่อการซ่อมบำรุง` (6,291) / `/STOCK` (84) | 6,375 | ฿20.3M | ❌ ไม่แสดง |
| ค่าแรง (`กลุ่มสินค้า` ขึ้นต้น `ค่าแรง`) | 4,053 | ฿8.3M | ❌ ตัดทิ้ง |

**เหตุผล:** ของที่ซื้อเข้าสต็อกกลางค้างเป็นเรื่องปกติตามธรรมชาติ แต่ของที่สั่งมาเพื่อรถคันหนึ่งโดยเฉพาะแล้วไม่เบิกไปใส่ = ปัญหาจริง · ค่าแรงไม่ใช่สินค้าคงคลัง ไม่มีวันค้างจริง

**ตำแหน่งที่กรอง — ต่างกันโดยตั้งใจ:**

- **ค่าแรง → กรองใน Mongo query** ปลอดภัยเพราะเป็นคุณสมบัติระดับ *รหัสสินค้า* (สินค้าตัวหนึ่งเป็นค่าแรงหรือไม่เป็น ไม่มีก้ำกึ่ง) ตัดทิ้งได้ทั้งฝั่งรับและฝั่งเบิกพร้อมกัน ไม่กระทบ FIFO ของสินค้าตัวอื่น
- **สต็อกกลาง → กรองตอนแสดงผล ห้ามกรองก่อน FIFO** เพราะเป็นคุณสมบัติระดับ *แถว* — รหัสสินค้าเดียวกันอาจรับเข้ามาทั้งแบบผูกรถและแบบเข้าสต็อกกลาง แต่ของจริงอยู่กองเดียวกันและถูกเบิกจากกองเดียวกัน **ถ้าตัดชั้นสต็อกกลางทิ้งก่อนตัด FIFO ยอดเบิกจะไปกินชั้นที่ผูกรถแทน → ของค้างจะดูน้อยกว่าจริง**

การตรวจจับทะเบียนใน `หมายเหตุ` ใช้ regex `/\/\s*[ก-ฮ]{0,3}\s*\d{1,3}-?\d{3,4}/` (รองรับทั้ง `71-5742` และ `กธ2607`)

## 4. ตรรกะ FIFO

ต่อ 1 รหัสสินค้า:

```
1. เรียง "ชั้นของ" (layer) จากใบ DD ตามวันที่ เก่า → ใหม่
   layer = { DD, วันที่, จำนวนรับ, ราคาทุน, ทะเบียนรถ (จากหมายเหตุ) }
2. รวมยอดเบิก (WD) ทั้งหมดของรหัสสินค้านั้น เรียงตามเดือน
3. ไล่ตัดยอดเบิกจากชั้นเก่าสุดก่อน จนหมดยอดเบิก
4. ชั้นที่ยังเหลือ = DD ที่ยังไม่ถูก WD ตัด
   อายุค้าง = วันนี้ − วันที่ DD
```

**สำหรับภาพรายเดือน** ทำซ้ำข้อ 3 โดยหยุดที่สิ้นเดือนแต่ละเดือน แล้ววัดอายุ ณ สิ้นเดือนนั้น

### เกณฑ์อายุ (ยึด 7 วันเป็นหลักตามที่ผู้ใช้กำหนด)

`0-7` · `8-15` · `16-30` · `31-60` · `60+` วัน — ตัวเลขที่เน้นบนทุกหน้าคือ **"ค้างเกิน 7 วัน"**

### ข้อจำกัดที่ต้องแสดงบนหน้าเว็บ ห้ามซ่อน

FIFO เริ่มนับที่ 2026-01 ไม่ใช่ศูนย์จริง — ของที่รับเข้ามาก่อนปี 2026 แล้วยังค้างอยู่จะมองไม่เห็น ผลคือมี **ยอดเบิก 1,872 หน่วยที่หาชั้น DD ในปี 2026 มาตัดไม่เจอ** (ของยกมาจากปี 2025) ต้องขึ้นเป็นหมายเหตุบนหน้าเว็บ ไม่ใช่ปัดทิ้งเงียบ ๆ

(ตรวจแล้วว่าไม่รุนแรง: แถวเบิกที่สินค้าไม่เคยรับเข้าเลยในปี 2026 มีแค่ 66 แถว = 0.2% ของยอดเบิก)

## 5. สถาปัตยกรรม

```
Mongo (2 aggregation)  →  FIFO ใน Node  →  API route (cache 1 ชม.)  →  3 หน้าเว็บ
     1.7 วินาที              21 ms
```

**ตัดสินใจสำคัญ: ห้ามลากแถวดิบมา Node** — วัดจริงแล้วดึง 54,069 แถวเต็มใช้เวลา **152 วินาที** แต่ยุบด้วย `$group` ฝั่ง Mongo ก่อนเหลือ 18,606 doc ใช้แค่ **1.7 วินาที (เร็วกว่า 90 เท่า)** และไม่เสี่ยง timeout บน Vercel

### Aggregation A — ชั้นรับ (11,934 doc / 1.27 วิ)

```js
{ $match: { inventory_id: "4", year_month: { $gte: "2026-01" },
            กลุ่มสินค้า: { $not: /^ค่าแรง/ }, รับ: { $gt: 0 } } }
{ $group: { _id: { i: "$รหัสสินค้า", d: "$DD", t: "$วันที่" },
            q: { $sum: "$รับ" }, c: { $last: "$ราคาทุน" },
            n: { $last: "$ชื่อสินค้า" }, g: { $last: "$กลุ่มสินค้า" },
            note: { $last: "$หมายเหตุ" } } }
```

### Aggregation B — ยอดเบิกรายเดือน (6,672 doc / 0.46 วิ)

```js
{ $match: { inventory_id: "4", year_month: { $gte: "2026-01" },
            กลุ่มสินค้า: { $not: /^ค่าแรง/ }, จ่าย: { $gt: 0 } } }
{ $group: { _id: { i: "$รหัสสินค้า", m: "$year_month" }, q: { $sum: "$จ่าย" } } }
```

## 6. หน้าเว็บ

### 6.1 `/deadstock` — ภาพรายเดือน
กราฟรายเดือน 2026-01 ถึงเดือนล่าสุด แสดง **จำนวนรายการ + มูลค่าค้าง** ณ สิ้นแต่ละเดือน โดยแยกส่วน "ค้างเกิน 7 วัน" ให้เด่น + การ์ดสรุปด้านบน (ค้างทั้งหมด / เกิน 7 วัน / มูลค่า / เกิน 60 วัน)

### 6.2 `/deadstock/pending` — สถานะล่าสุด (หน้าหลักที่ใช้งานจริง)
ตาราง DD ที่ยังค้าง: `DD · วันที่รับ · ทะเบียนรถ · รหัส/ชื่อสินค้า · กลุ่มสินค้า · คงเหลือ · ราคาทุน · มูลค่า · อายุค้าง (วัน)` แถบสีตามช่วงอายุ · เรียง/กรองตามอายุและกลุ่มสินค้า · ค้นหาด้วยทะเบียน/รหัส/เลข DD · **export Excel** (repo มี `xlsx` แล้ว)

### 6.3 `/deadstock/items` — รายรหัสสินค้า
ยุบตาม SKU: คงเหลือรวม/มูลค่ารวม/อายุของชั้นเก่าสุด กดขยายดูว่าค้างมาจาก DD ใบไหนบ้าง

## 8. การทดสอบ

- **FIFO engine** — unit test บนข้อมูลสมมติ: ตัดข้ามหลายชั้น, ตัดพอดีหมดชั้น, ยอดเบิกเกินของที่มี (unmatched), ชั้นวันที่เดียวกัน, จำนวนทศนิยม
- **ตัวตรวจทะเบียน** — test regex กับรูปแบบจริงทั้ง 3 แบบ (`71-5742`, `กธ2607`, `เข้าสต๊อกเพื่อการซ่อมบำรุง`, `/STOCK`)
- **ระดับ integration** — เทียบผลกับตัวเลขข้อ 7
- **ตรวจ query plan** — ยืนยันว่ายังเป็น `IXSCAN` ไม่ใช่ `COLLSCAN`

## 9. สิ่งที่ไม่ทำในรอบนี้ (YAGNI)

- คลังอื่นนอกจากลาดกระบัง — โครงรองรับได้ (แค่เปลี่ยน `inventory_id`) แต่ยังไม่เปิด
- ย้อนหลังก่อนปี 2026
- เขียนข้อมูลกลับ / เวิร์กโฟลว์จัดการของค้าง (แจ้งเตือน, มอบหมายงาน, ปิดรายการ)
- cron precompute — ยังไม่จำเป็นเพราะ 1.7 วินาที
